# 四轴滑轨：手动原点 / 上电自检 / HTTP GET 毫米定位

每次上电前，先手动将四个滑块放到各自的物理原点。固件上电把当前位置记为 0 mm，不再寻找原点，也不使用限位开关。随后四轴一起前进 10 mm，再一起返回原点，完成后接受毫米绝对位置指令。

## 引脚和参数

| 轴 | PUL GPIO | DIR GPIO | 有效行程 mm | 每电机圈移动 mm | 每圈脉冲 |
|---|---:|---:|---:|---:|---:|
| M1 | 4 | 5 | 100 | 2 | 6400 |
| M2 | 6 | 7 | 100 | 2 | 6400 |
| M3 | 9 | 10 | 100 | 2 | 6400 |
| M4 | 11 | 12 | 100 | 2 | 6400 |

GPIO12 仅作 M4 的 DIR 输出；GPIO13、14、15 没有配置或读取，不再占用为原点输入。

机械参数已按你的滑台设为螺距/导程 2 mm、行程 100 mm、驱动器 6400 脉冲/圈（按无减速、每圈移动 2 mm 换算），在 `include/rail_config.h` 修改：

- `lengthMm`：从手动原点到允许的正向终点的行程，保留机械端点余量。
- `mmPerRev`：电机一圈对应滑块移动量，包含丝杆导程或减速比的影响。
- `pulsesPerRev`：与电机步距角、驱动器细分一致。
- `positiveDirLevel`：使位置增大的 DIR 电平；正转应远离手动原点。
- `SELF_TEST_ON_BOOT=true`：启用上电动作自检；关闭后仍把上电位置记为 0。
- `SELF_TEST_RPM=15`：自检及默认定位转速为 15 RPM，配合加减速。
- `SELF_TEST_DISTANCE_MM=10`：前进自检距离为 10 mm，然后返回 0 mm。
- `SELF_TEST_TIMEOUT_US=120000000`：每段最长等待 120 秒，是故障超时，不是固定运动时长。

默认分辨率为 `2/6400=0.0003125 mm`（3200 脉冲/mm）；目标按整脉冲量化，最大位置向下取整。分辨率不等于实际机械精度。

## 上电自检和手动原点

### 更改驱动器细分，保持距离正确

在 `include/rail_config.h` 顶部的 `MOTOR1_PULSES_PER_REV` 到 `MOTOR4_PULSES_PER_REV` 分别设置四轴的**每圈脉冲数**。默认都是 6400；修改后重新编译、烧录，下次上电自检和全部毫米定位自动使用新值。驱动器的拨码/设置也必须同步修改，软件无法替你改变驱动器细分。

填写面板上的 `pulse/rev`，例如 3200、6400、12800，不能把“32细分”的 32 直接填进去。对 1.8° 电机，32 细分对应 `200 × 32 = 6400` 脉冲/圈。2 mm 导程下，`1 cm = 10 mm = 5 圈`，因此 3200/6400/12800 脉冲每圈时，移动 1 cm 分别需要 16000/32000/64000 个脉冲。程序会自动换算。

也可在设备运行且对应轴空闲、自检结束后，用现有 GET 接口临时设置：

```text
/api/set?motor=2&param=ppr&value=3200
```

查询 `/api/result?id=返回的请求ID` 确认成功后，检查实际驱动器已匹配、手动把该轴放到原点，再发送 `/api/zero?motor=2`。运行时更改 PPR 会使该轴原点失效，防止旧脉冲数被当作新比例的位置；确认零位后可以正常发送毫米目标，例如 `/api/move?motor=2&mm=10&rpm=5`。**GET 设置仅保存在 RAM，重启恢复头文件数值**；长期更改请修改头文件并烧录。

细分越高，同一 RPM 所需脉冲频率越高。当前最大 2000 Hz，因此 `最高 RPM = 120000 / PPR`。例如 12800 脉冲/圈时最高 9.375 RPM，需同步把 `SELF_TEST_RPM` 调低；普通定位可传入合适的 `rpm` 或修改默认转速。

### 启动步骤

1. 断电时手动把四个滑块放到各自原点，再上电；复位同样会把复位时的位置当作原点。
2. 四轴同时前进 10 mm：每轴转 5 圈、输出 32000 个脉冲。等全部轴到达 10 mm 后，再一起反转相同脉冲数返回 0 mm；两段均加减速。
3. 在当前 15 RPM、800 脉冲/s² 加速度下，单程约 22 秒，全程约 44 秒（实际受调度影响），完成后进入正常定位。自检期间拒绝定位、清零和参数修改，状态查询和停止可用。自检时间使用任务调度，方向切换可能有少量调度延迟。
4. 不会在自检结束时强行把坐标清零；若运动超时或越界，停止全部轴，报告 `failed`，位置失效。检查后手动放回原点，再使用单轴 `/api/zero?motor=1` 等恢复坐标，或在原点重新上电。

自检期间 `/api/stop` 或单轴 STOP 都会取消整个自检、停止四轴；保留停止时的累计位置，不会自动继续或归零。正常定位期间单轴 STOP 只停止对应轴。

没有传感器，自检只能检查固件发脉冲流程，不能判断电机是否实际转动、是否接线正确或丢步。每次上电前手动位置必须正确；软件限位和位置反馈都基于这个假设。

## GET 接口

将以下 IP 替换为设备实际 IP；也可使用 `http://esp32-stepper.local`。Wi-Fi 私密配置仍在 `include/device_config.local.h`，按 `.example` 文件填写。

| 用途 | GET 示例 |
|---|---|
| 一条指令定位四轴 | `/api/move_all?m1=10&m2=20&m3=30&m4=40` |
| 四轴指定同一 RPM | `/api/move_all?m1=10&m2=20&m3=30&m4=40&rpm=15` |
| 单轴绝对定位 | `/api/move?motor=2&mm=25.5&rpm=15` |
| 状态及当前位置 | `/api/status` |
| 手动放到原点后记录单轴零位 | `/api/zero?motor=2` |
| 全部停止 | `/api/stop` |
| 单轴停止 | `/api/stop?motor=2` |
| 查询请求执行结果 | `/api/result?id=1` |
| 设置单轴默认转速 | `/api/set?motor=2&param=rpm&value=15` |

`m1..m4` 和 `mm` 的单位都是 **mm，含义为从原点算起的绝对位置**。例如当前 10 mm，发送 50 mm 就走到 50 mm；再次发送 50 mm 不会继续走。四轴参数必须全部给出，0 表示定位到原点。RPM 可省略，采用各轴默认值；它不是 mm/s。

每轴只允许 `0 <= 目标 <= 本轴 lengthMm`。整组目标、速度、原点有效状态和忙状态全部检查通过后才会启动任何轴；任一轴不通过就整组拒绝，不会截断成边界值。小数、负数、NaN、重复参数等均按规则严格检查。旧 HTTP `turns/t1/r1...` 参数不再接受，应改用上述毫米参数。内部保留的 MOVE/MOVEALL 圈数解析同样受原点有效性和行程校验约束。

控制请求先返回 `202`，例如：

```json
{"accepted":true,"id":1,"result_url":"/api/result?id=1"}
```

随后 GET `/api/result?id=1`：仍排队返回 202；校验和启动成功返回 200；越界、原点失效等返回 400；忙返回 409；队列满或任务不可用返回 503。**202 只表示入队，结果 200 表示指令执行/启动成功，都不表示已经到位。** 请求结果仅保留最近 16 条，重启清空；自检或运动中的后续故障通过状态查询获知。网络超时后先查状态，不自动重复发送运动指令。

四轴共用启动时刻、各自加减速，不保证同时到达。希望只动一轴时使用 `/api/move`；整组接口没有“0 表示跳过”的语义。

## 当前位置反馈

GET `/api/status` 返回四轴快照，约每 20 ms 更新；快照超过 500 ms 未更新时返回 503。上位机可以每 100～200 ms 轮询一次。单轴字段示意：

```json
{
  "motor": 2,
  "moving": false,
  "homed": true,
  "home_state": "ready",
  "position_mm": 25.5,
  "target_mm": 25.5,
  "length_mm": 100,
  "mm_per_rev": 2,
  "fault": ""
}
```

实际响应还保留 `position`（原始脉冲数）、`ppr`、`completed`、`total` 等字段。`homed=true` 和 `home_state="ready"` 为兼容旧版字段，当前含义是手动原点有效，不代表传感器回零成功。原点失效或故障时，`position_mm`、`target_mm` 为 `null`。

顶层 `origin_mode="manual_on_boot"`，`position_source="commanded_steps"`。`auto_active` 表示自检进行中，`self_test` 为 `pending/forward/reverse/passed/failed/cancelled/disabled`。上位机等 `self_test="passed"`、四轴空闲且原点有效后再下发首次定位；关闭自检时为 `disabled`。

正常运动逐脉冲检查 `0..lengthMm` 软件范围，不读取任何限位输入。`/api/home` 路径保留但返回错误，提示使用手动原点。`/api/zero?motor=N` 只在对应轴空闲且自检结束后执行，并把当前位置记为 0；执行前必须由你确认该轴实际处于原点。

**反馈来自累计脉冲，不能检测丢步、卡滞或人为移动。** 软件限位只能保护正确原点和未丢步前提下的指令范围。STOP 没有减速过程；位置不可信时手动恢复原点，再记录零位。更改 PPR 后会使原点失效，需要重新确认和记录零位。RGB 故障显示红色。

## 上位机示例与编译

图形上位机：双击 `examples/start_controller.cmd`，或运行 `python examples/slider_controller.py`。四个滑块范围 0～10 cm，自动转换为 GET 接口的毫米目标，并显示实时位置。离线预览运行 `python examples/slider_controller.py --demo`。操作说明见 [examples/SLIDER_CONTROLLER.md](examples/SLIDER_CONTROLLER.md)。

在 `ESP Step` 目录运行：

```powershell
python examples/http_client.py status
python examples/http_client.py move_all m1=10 m2=20 m3=30 m4=40
python examples/http_client.py move motor=2 mm=25.5 rpm=15
python examples/http_client.py zero motor=2
python examples/http_client.py stop
python examples/http_client.py --base http://192.168.1.100 status
```

脚本会查询请求执行结果；是否到位/自检完成需继续查询 status。HTTP 与运动任务以队列交换命令和快照，网络阻塞不会阻塞脉冲调度。每轴最大 2000 Hz、RPM 1～300（还需满足频率限制），默认加速度 800 脉冲/s²、默认 15 RPM。6400 脉冲/圈下，由 2000 Hz 限制得到最高允许 18.75 RPM，约 0.625 mm/s；更高转速会被拒绝。`/api/set` 的 `ppr/rpm/accel` 仅在空闲时修改、仅保留在 RAM。持久机械配置请修改头文件后编译。

```powershell
pio run -e esp32s3_uart
pio run -e 4d_systems_esp32s3_gen4_r8n16
```

保留现有板型和 COM10 配置，需按实际开发板修改。固件编译与主机模拟验证不能替代实际电机接线、正反方向、带载运动、Wi-Fi 和脉冲波形验证。主机测试说明见 `test/host/README.md`。50 μs 为软件调度目标周期，仍存在系统抖动。以下保留既有驱动器接线说明。

## 1. 先设置驱动器

**暂未找到能核实厂家和版本的 DM42L 原厂手册。以下采用 PUL/DIR 常见接口方案，不把其他型号的参数当作 DM42L 参数。接线前按实际标签/卖家说明核对供电范围、输入信号电压、输入电流、脉冲有效沿和 ENA 悬空行为。**

- 你现有电源是 12V：仅当驱动器标注的直流供电范围包含 12V 时才能使用。若标注最低电压高于 12V，需换电源。12V 供电时高速力矩也可能受限。
- 工作模式选 **PUL + DIR（单脉冲 + 方向）**，不要选双脉冲 CW/CCW。
- 驱动器已设置 **6400 pulse/rev（脉冲/圈）**，固件四轴也设置为 6400；以后修改拨码时，务必同步修改配置。
- 对于 1.8° 电机，32 细分为 200 × 32 = 6400 脉冲/圈；以驱动器面板的 pulse/rev 标注为准。当前按无减速、丝杆每圈移动 2 mm 换算。
- 电流按电机铭牌的额定相电流及驱动器标注的峰值/RMS定义选择，初试可选较低档，不能仅凭 12V 决定。若电机标 RMS、驱动器表列峰值，需按厂家说明换算。
- 修改接线和拨码前断电，禁止带电插拔电机线。

## 2. 接线

当前工程保留已有板型 `4d_systems_esp32s3_gen4_r8n16`；该配置不代表已确认实际开发板型号。若使用普通 ESP32-S3 开发板，请在 PlatformIO 中选择实际型号，并确认 GPIO4、GPIO5 可用且没有连接板载外设。代码编号是 GPIO 编号，不是排针物理序号。

### 电源和电机

| 驱动器端子 | 接线 |
|---|---|
| V+ / DC+ | 12V 电源正极（确认驱动器支持 12V） |
| V- / GND | 12V 电源负极 |
| A+、A- | 电机同一相的两根线 |
| B+、B- | 电机另一相的两根线 |

断电后用万用表识别绕组：同一绕组两线间有电阻；不要只按颜色猜。ESP32 用 USB 供电，**不能将 12V 接入 ESP32 的 5V、3V3 或 GPIO**。

### 控制信号：推荐外接 NPN 共阳转换

ESP32 为 3.3V GPIO；驱动器光耦输入未必能由 3.3V 可靠驱动。本方案使用两路 NPN 开集电极转换（或明确支持 3.3V 输入、5V 光耦驱动输出的高速模块）。仅在确认 DM42L 支持 5V 信号且输入限流符合要求后，采用下面的 5V 共阳接法；若它要求别的电压，按该版本手册重新配置接口。

| 驱动器端子 | 连接 |
|---|---|
| PUL+ | 稳定的逻辑 +5V |
| PUL- | Q1 集电极 C |
| DIR+ | 同一逻辑 +5V |
| DIR- | Q2 集电极 C |
| ENA+、ENA- | **两端均悬空**，前提是手册确认悬空默认使能 |

每一路可用 S8050 / 2N2222 等 NPN：GPIO4 → 1kΩ 电阻 → Q1 基极 B；GPIO5 → 1kΩ 电阻 → Q2 基极 B。两个发射极 E 均接 ESP32 GND；每个 B 与 E 间加 10kΩ 下拉，防止复位时悬空。5V 逻辑电源负极也接 ESP32 GND。不同封装的三极管 B/C/E 排列不同，按其数据手册确认。

5V 应来自 USB 5V 或合规降压模块，不能来自 ESP32 的 3V3。驱动器光耦信号回路通过上述三极管闭合；驱动器的电机电源负极不应被误接为 PUL-。是否另需连接驱动器电源地，以实际手册为准。信号线短接、与电机线分开走线。

GPIO 输出高时三极管导通，PUL- 被拉低；输出低时释放。代码每次保持导通至少 10µs，并完成整个导通/释放周期，DIR 在首脉冲前至少建立 100µs。这些是本程序选用的时序，仍须确认满足你的 DM42L 最小时序和转换电路要求。不要把上述外接三极管接法与 GPIO 直连接法混用。

ENA 不影响实现基本正反转和圈数。若该版本悬空不使能，必须按其说明处理 ENA；当前程序没有 ENA 输出控制，也没有释放电机功能。
