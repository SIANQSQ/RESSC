# 四轴滑台桌面上位机

使用 Python 自带 Tkinter 界面，无需安装第三方依赖。需要带 Tkinter 的 Python 3.9 或更新版本（Windows 官方 Python 安装器通常自带）。

## 启动

双击同目录 `start_controller.cmd`，或在工程目录运行：

```powershell
python examples/slider_controller.py
python examples/slider_controller.py --base http://192.168.1.100
```

不连接真实设备的演示：双击 `demo_controller.cmd`，或运行：

```powershell
python examples/slider_controller.py --demo
```

演示模式显示四个模拟滑台，不向网络发送任何指令；其中运动速度仅用于界面预览。

## 操作

1. 上电前手动将四个滑台放到原点；电脑与 ESP32 连接同一局域网。
2. 在设备地址中输入 IP（如 `192.168.1.100`）或完整根地址，然后点击“连接设备”。连接时仅查询状态，不会发送定位指令。
3. 等上电自检结束、四轴空闲且原点有效，界面会同步当前位置并启用四个滑块。连接时如果设备正在运动，会先等待空闲。
4. 四个滑块和右侧数字框均以 **cm** 显示，范围 **0～10 cm**。青色滑块表示设备反馈的当前位置，橙色竖线表示界面目标。
5. **“拖动后自动发送”默认关闭**。调整滑块或数值后，点击“发送四轴目标”才会下发运动指令。可选“四轴同步拖动”：开启后，拖动或修改任一轴的目标，会将四个目标同步设为相同位置；关闭后各轴独立。同步开关默认关闭，切换开关本身不会改变位置或发送命令。
6. 如果勾选自动发送，拖动停顿约 350 ms 后保存最新目标；设备空闲时通过一条 GET `/api/move_all` 发送。运动中继续拖动只保留最新目标，等本次运动结束再执行。同步和自动发送可以独立组合使用。取消自动发送会清除尚未发送的本地目标，已经发送到设备的运动会继续。
7. “四轴回到 0 cm”发送绝对位置 0，表示移动回现有原点；**不会调用软件清零接口**。
8. “停止全部运动”清除待发目标并发送 `/api/stop`。自检中也可用。网络 STOP 仍受网络和设备命令队列延迟影响，不是硬件急停。

## URL 和单位

界面底部预览实际 URL。滑块设置 `1、2、3、4 cm`，会发送：

```text
http://设备IP/api/move_all?m1=10&m2=20&m3=30&m4=40&rpm=15
```

接口参数仍为 **mm**，即 `URL 位置 = 界面 cm × 10`。当前每轴行程 100 mm，因此下面的原示例会被设备拒绝：

```text
/api/move_all?m1=50&m2=100&m3=150&m4=200
```

其中 M3 的 150 mm 和 M4 的 200 mm 超过 10 cm 行程。直接浏览器调用可以改成：

```text
http://设备IP/api/move_all?m1=25&m2=50&m3=75&m4=100
```

这对应界面的 `2.5、5、7.5、10 cm`。返回 202 表示命令入队，查询响应中的 `result_url` 确认启动成功；最终到位仍应查看 `/api/status`。上位机自动完成结果查询和约每 200 ms 的状态轮询（实际周期取决于网络）。

转速输入单位是 RPM。程序读取设备返回的每轴 `ppr`，检查当前允许的最高转速 `120000 / ppr`；例如 6400 脉冲/圈时不超过 18.75 RPM。界面不修改细分、不修改设备原点，也不更改现有固件。

## 连接中断

网络请求在后台线程执行，拖动界面不会等待网络返回。断线或请求结果不确定时，会禁用定位并清除待发目标；不会自动重发运动命令。重新连接后先读取实际状态、等待空闲，再重新操作。

断开连接或关闭窗口不会自动停止设备已经启动的运动。需要停止时，先点击停止并等待反馈。切换设备地址时先断开，再输入新地址并连接。

位置反馈来自固件累计输出的步数，不是编码器测量，无法识别丢步或滑台被人为移动。

## 验证

```powershell
python -m py_compile examples/slider_controller.py
python -m unittest discover -s test -p test_slider_controller.py -v
```

测试覆盖 cm/mm 换算、0～10 cm 边界、整组 GET 的真实 HTTP 编码、运动期间合并目标、202/执行结果区分、忙状态、停止、自检/故障阻止发送、设备行程和频率限制、未决结果不重发。测试使用模拟设备和本机 HTTP 服务，不连接实机。
